A bounded experiment on real scientific claims and held-out relevance labels (BEIR SciFact), repeated on the client's HR-policy corpus in a separate section below. It is designed to expose the quality, latency, and storage trade-offs inside the retrieval stack—not to recreate a production system or compare against Elasticsearch.

COMPARISON PLAN

What changes in each set

01 · MODEL

Retrieval quality

voyage-4-large, voyage-4, and voyage-4-lite at 1024 dimensions. This isolates the general-model quality/cost/latency choice.

02 · CONTEXT

Chunk-aware embeddings

voyage-context-4 encodes the chunks of a paper together. It is compared with general embeddings of the same chunk text, rather than assumed to be better.

03 · DIMENSION

Matryoshka reduction

voyage-4 at 1024, 512, and 256 dimensions. Lower dimensions reduce vector and index footprint; the labels show whether the quality loss is acceptable.

04 · ATLAS BEHAVIOUR

Index trade-offs

Float versus scalar quantization, then numCandidates 100, 400, and 1000. ANN-to-ENN overlap is retained for the candidate-curve rows.

READING THE RESULT

Quality first, then the cost of getting it

Recall@10
Share of labelled relevant papers retrieved in the top ten documents.
MRR@10
How quickly the first relevant paper appears.
nDCG@10
Ranking quality, using the relevance labels and position.
P50 / P95
Client-observed Atlas retrieval time, one query at a time. Not a throughput claim.
ANN–ENN overlap
Approximate-search agreement with an exact reference for the candidate curve.

BOUNDARY

This does not answer application end-to-end latency, concurrent capacity, or performance at millions of vectors. Hybrid retrieval and ACL pre-filtering are measured, with limits: the SciFact ACL groups are synthetic (assigned by hashing the document id), and the client dataset uses real audience rules but a single test user, so it cannot show leakage between users. A later workload-specific benchmark is needed for the rest.

Separate from the SciFact rows above. Every query is pre-filtered to the documents its asker may see. Doc Hit@N: a returned section belongs to a gold document within the first N sections; Passage Hit@N: a returned section is a gold section, scored only on queries that have gold sections. Table-to-text sentences are indexed as extra pieces of the section that holds each table, and a result list holds each section once, at the rank of its best piece, so it can contain fewer than 50 sections. Scored on answerable queries; unanswerable queries are reported separately. Recall, MRR and nDCG@10 are computed on documents after deduplicating sections.
