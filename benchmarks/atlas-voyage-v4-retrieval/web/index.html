COMPARISON PLAN

What changes in each set

01 · MODEL

Retrieval quality

voyage-4-large, voyage-4, and voyage-4-lite at 1024 dimensions. This isolates the general-model quality/cost/latency choice.

02 · CONTEXT

Chunk-aware embeddings

voyage-context-4 encodes the chunks of a paper together. It is compared with general embeddings of the same chunk text, rather than assumed to be better.

03 · DIMENSION

Matryoshka reduction

voyage-4 at 1024, 512, and 256 dimensions. Lower dimensions reduce vector and index footprint; the labels show whether the quality loss is acceptable.

04 · ATLAS BEHAVIOUR

Index trade-offs

Float versus scalar quantization, then numCandidates 100, 400, and 1000. ANN-to-ENN overlap is retained for the candidate-curve rows.

READING THE RESULT

Quality first, then the cost of getting it

Recall@10
Share of labelled relevant papers retrieved in the top ten documents.
MRR@10
How quickly the first relevant paper appears.
nDCG@10
Ranking quality, using the relevance labels and position.
P50 / P95
Client-observed Atlas retrieval time, one query at a time. Not a throughput claim.
ANN–ENN overlap
Approximate-search agreement with an exact reference for the candidate curve.

BOUNDARY

This deliberately does not answer application end-to-end latency, concurrent capacity, ACL correctness, hybrid retrieval, or performance at millions of vectors. Those need a later workload-specific benchmark.
